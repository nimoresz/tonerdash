# Toner Dashboard 4 (Docker)

Мониторинг расходников принтеров: SNMP (Printer-MIB + Pantum) и чтение уровня с веб-страницы принтера,
история уровней, дашборд, REST API, метрики Prometheus. Бывший `Toner-Dashboard.ps1`, перенесённый в Docker.

```
┌──────────── docker compose ────────────┐
│ secrets  одноразово генерирует пароль БД│
│ db       PostgreSQL 16 (сеть backend,   │
│          наружу не опубликован)         │
│ app      Python: опрос + веб + API ─────┼──► http://localhost:8080
│          (сети backend + frontend) ─────┼──► принтеры в LAN (SNMP UDP/161, HTTP)
└─────────────────────────────────────────┘
```

## Запуск

Одинаково на Docker Desktop (Windows/macOS) и на Linux-ВМ с Docker Engine + compose plugin:

```bash
cd toner-docker
docker compose up -d --build
docker compose logs app
```

Откройте http://localhost:8080/, войдите как `admin` со стартовым паролем из логов (строка `Start password`) — система сразу попросит задать свой.

Настройки по умолчанию подходят без `.env`. Чтобы поменять порт, подсети и т.п.:

```bash
cp .env.example .env
```

**Linux-ВМ, в которую заходите с другого компьютера:** в `.env` поставьте `BIND_ADDR=0.0.0.0`
и откройте `http://<ip-вм>:8080/` (или пробросьте порт по SSH: `ssh -L 8080:localhost:8080 user@vm`,
тогда работает тот же `http://localhost:8080/`).

## Полезные команды

| Что | Команда |
|---|---|
| Статус и healthcheck | `docker compose ps` |
| Логи опроса | `docker compose logs -f app` |
| Забыли пароль (новый стартовый + выход всех сессий) | `docker compose exec app python -m toner reset-password` затем `docker compose restart app` |
| Обновить после правок кода | `docker compose up -d --build` |
| Бэкап БД | `docker compose exec db pg_dump -U toner toner > toner.sql` |
| Восстановление | `docker compose exec -T db psql -U toner toner < toner.sql` |
| Остановить | `docker compose down` (данные остаются в томе `pgdata`) |
| Снести вместе с данными | `docker compose down -v` |
| Демо-данные | `DEMO=true` в `.env` |

Логотип: положите `logo.svg`/`logo.png` в папку `branding/`.

## Что изменилось по сравнению со скриптом

**Работает так же:** сканирование подсетей, ручное добавление IP, SNMP-запрос к любому принтеру, веб-фолбэк для Pantum,
«последнее известное состояние» у выключенных принтеров, переименование/скрытие, история и спарклайны, CSV, Prometheus,
все пути REST API (`/api/printers`, `/api/supplies`, `/api/replace`, `/api/stats`, `/api/metrics` …).

**Убрано:** очереди Windows-принт-сервера (`Get-Printer`) — в Linux-контейнере их нет. Принтеры находятся
сканированием подсетей и добавляются вручную по IP (раздел «Управление»).

**Хранение:** вместо JSON-файлов — PostgreSQL (настройки, принтеры, история, переопределения, сессии, хеш API-токена).

### Производительность

- Свой асинхронный SNMP-клиент: десятки OID в одном пакете, полный опрос принтера — 3–4 UDP-запроса вместо ~80.
- Опрос принтеров параллельный (16 одновременно), сканирование — пул из 192 воркеров; 12 подсетей /24 сканируются за секунды.
- Автоопределение SNMP v2c/v1 с запоминанием версии для каждого принтера.
- Ответ `/api/printers` кешируется вместе с gzip и отдаётся по ETag (304 без тела).
- Статика в памяти, предсжата; шрифт встроен в образ (страница ничего не грузит из интернета).
- Лимиты: app 256 МБ / 1 CPU, db 256 МБ / 0.5 CPU; PostgreSQL настроен под маленькую нагрузку. Ожидаемо в простое — десятки МБ RAM (не замерялось).

### Безопасность

- Контейнеры: `read_only` файловая система, `cap_drop: ALL`, `no-new-privileges`, непривилегированный пользователь (uid 10001),
  лимиты памяти/CPU/процессов, ротация логов.
- БД в изолированной сети `internal: true`, порт не публикуется; пароль БД случайный, генерируется при первом запуске
  и лежит в приватном томе (не в `.env` и не в переменных окружения).
- Веб по умолчанию слушает только `127.0.0.1`.
- Пароль администратора — scrypt; стартовый пароль одноразовый. Токены сессий и API-токен хранятся только как SHA-256.
- API-токен показывается один раз при выпуске и даёт только чтение + запуск опроса (без изменения настроек).
- Защита от перебора: 5 ошибок с адреса → блок 5 мин; 20 ошибок со всех адресов за 15 мин → блок входа 5 мин.
- CSRF: cookie `HttpOnly; SameSite=Strict` + обязательный заголовок и проверка Origin/Sec-Fetch-Site для POST.
- Заголовки: строгий CSP (без inline-скриптов), `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: no-referrer`, COOP/CORP.
- SNMP-запросы и добавление принтеров разрешены только для частных адресов LAN (без loopback, link-local и интернета).
- CSV защищён от формул-инъекций в Excel; размер тела запроса ограничен 64 КБ.

> На Docker Desktop все клиенты видны сервису с одного адреса шлюза Docker, поэтому блокировка после
> неверных паролей действует сразу на всех. Для HTTPS поставьте перед сервисом reverse proxy и включите `COOKIE_SECURE=true`.

## Сети

Docker-сети зафиксированы на `172.29.10.0/24` и `172.29.11.0/24`, чтобы Docker не занял диапазон `192.168.x`, где живут принтеры.
Если в вашей сети используется `172.29.x`, поменяйте подсети в конце `docker-compose.yml`.
